ROOT CAUSE DIAGNOSIS:
1. Why irrigation_events = 0 in test set:
   The chronological test set spans index 4231 to 5000.
   In V1 synthetic_generator, scenario assignment was blocked in chronological order:
   - Hours 0-1000: NORMAL_BALANCED (auto-irrigate enabled)
   - Hours 1000-1800: HOT_HIGH_ET0 (auto-irrigate enabled)
   - Hours 1800-2400: MONSOON (auto-irrigate disabled, rain)
   - Hours 2400-3400: DROUGHT (auto-irrigate disabled, deficit only)
   - Hours 3400-4200: PASSING_SHOWERS (rain frequent)
   - Hours 4200-5000: AUTUMN_MIXED
   Because the test set fell entirely in AUTUMN_MIXED (hours 4235-4983), where moisture remained
   moderate (~26-34%) and rain showers occurred every 25 hours, soil moisture never dropped below the
   hardcoded trigger threshold (MAD = 50% => 23.5% moisture). Thus, zero irrigation events occurred in the test window.

2. Why low_moisture_near_wilting = 0 in test set:
   The severe drought regime was localized entirely in hours 2400-3400, which fell exclusively in the
   TRAINING split! Neither the validation split nor the test split ever experienced severe drought.

3. Why rain-event ML failed against persistence (-28.4%):
   At time t, the ML model features only observed precipitation that ALREADY occurred (rainfall_mm,
   rolling_rain_6h) and a static 24h aggregate forecast. The model did NOT receive an explicit forecast
   for the 3-hour prediction horizon (forecast_rain_next_3h_mm). When rain began unexpectedly between
   t+1 and t+3, the actual moisture spiked up by +2% to +8%. Because ML tried to predict drying while
   persistence remained frozen, ML's error was wider than persistence's static lag error!
